# 管理端产品与界面设计

## 目标与使用场景

当前规模是三个账户，网络目录需要能继续维护和扩充。管理员维护网络名称、说明与账户授权；普通用户查看自己的授权及登记记录。登录页仅用“账户 → 授权 → 网络资源”表达关系，不公开真实环境名称。管理网页不能代替系统 VPN 客户端，也不能把设备登记数量解释为设备准入或在线数量。

本轮直接基于代码设计、浏览器预览与验收，沿用用户已批准的方式。保留静态 HTML / CSS / ES 模块与 Python API。网络目录使用增量数据库迁移；不变更 VPN 服务。新增目录为草稿，需单独验证网关和路由后才能开放授权。

## 任务结构

| 页面 | 首要任务 | 主要内容与操作 | 必须说明的边界 |
| --- | --- | --- | --- |
| 登录 | 使用现有账户进入控制台 | 服务状态、账户名、密码、可恢复错误 | 刷新后重新登录；不保存密码或会话令牌到磁盘 |
| 访问概览 | 看清自己能访问哪些网络 | 账户身份、授权网络、接入同步状态、连接说明、本人设备记录 | 授权不等于已经连接；状态来自 API |
| 网络环境 | 维护网络目录 | 名称与说明编辑、搜索、新增草稿、版本冲突提示 | 稳定标识不随名称变化；草稿不能授权或自动接通 |
| 账户与授权 | 分配角色与网络权限 | 完整账户列表、账户搜索、状态筛选、编辑、网络授权、设备入口、停用 | 系统管理员不能降级或停用；普通用户仅工作权限 |
| 设备登记 | 按账户维护设备记录 | 账户选择、登记配额、设备状态、登记与移除 | 每账户十条登记上限，不是身份验证或 VPN 准入 |
| 登录审计 | 追查登录及管理操作 | 时间、账户、动作、结果、来源、游标分页 | 展示管理服务审计，不伪称所有 VPN 连接日志 |

管理员页面按角色提供入口，后端继续承担权限校验。普通用户不会获取管理员列表。搜索和状态筛选仅使用已获授权的完整账户响应，不引入额外数据接口。

## 状态、结构与数据所有权

页面仍由 `index.html` 的语义结构、`styles.css` 的视觉令牌及 `app.js` 的状态/事件/渲染承担职责，`config.json` 只提供公开部署配置。当前没有足以支持引入构建系统、SPA 路由或状态库的复杂度证据。

| 事实或状态 | 权威来源 | 生命周期与恢复 |
| --- | --- | --- |
| 身份、角色、网络授权、设备记录、审计 | 已认证 API 与现有数据库 | 页面不计算真实准入；401 清空当前内存会话并回到登录 |
| 完整账户响应 | `state.users` | 读取前使旧响应过期；成功后供筛选派生，失败隐藏旧表格 |
| 搜索与状态筛选 | 当前输入控件 | 跨功能导航保留，退出或切换账户清空 |
| 编辑草稿 | 原生表单 | 每次打开从当前账户初始化；取消不写入；服务端错误保留草稿 |
| 审计游标与页码 | API 游标 + `state.auditCursors` | 上下页依游标读取；刷新回第一页；退出清空 |
| 会话令牌与 CSRF | API 登录响应 | 仅内存持有；不写 URL、磁盘或浏览器持久存储 |

请求适配仍由 `apiRequest` 统一执行认证、CSRF、序列化、取消和错误映射。可被替代的列表请求保留序号保护；页面事件只派生显示，不增加身份、路由或数据库事实的副本。

## 视觉与交互规则

- 深色侧栏承载稳定导航，浅色工作区承载任务；蓝绿色为操作色。使用系统中文字体，不加载第三方字体、统计或图标脚本。
- 统一间距、圆角、边框、文字与状态色变量。页面标题、说明、操作和数据表形成明确层次；小规模数据不制造空图表或虚假指标。
- 表格保留原生语义、可读的列标题、清晰操作名称；账户与网络用文字及形状表达，不能只靠颜色区分。
- 短表单使用原生 `dialog`，支持 Escape、焦点约束和关闭后返回触发入口。验证失败保留已填内容；提交期间禁止重复提交。
- 加载、空列表、筛选无结果、网络错误、会话失效分别呈现。错误不清空账户输入，不以空表格冒充请求成功。
- 窄屏使用可横向滚动的表格区域，不让整页产生横向溢出；导航、表单、按钮保留触控与键盘操作空间。

## 不变的服务边界

继续使用严格 CSP、精确 API Origin、内存 Bearer 会话、CSRF 和后端角色授权。固定系统管理员 `guanxiangkai` 的保护由后端事务校验，不能通过新增第二个管理员绕过；前端同时禁用对应控件。

数据库从 v6 增量升级为 v7，新增 `network_catalog`。现有账户、会话、授权、网关投递数据保持原值；网络资料更新有版本比较和审计。旧版程序拒绝 v7，发布前必须保存一致的数据库快照与旧代码，并使用独立自动回滚。网络资料不写网关 outbox，不修改 VPN 网关、家庭/工作路由或现有 VPN 进程。

## 来源与采用范围

核对日期：2026-11-03。

- [IBM Carbon 数据表无障碍](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/accessibility)：采用原生表格及交互控件的语义、键盘与标签原则；不引入 Carbon 框架依赖。
- [W3C H102 原生 dialog](https://www.w3.org/WAI/WCAG22/Techniques/html/H102)：沿用浏览器提供的模态与焦点管理；实际检查键盘及关闭行为。

技能维护归属 Codex 既有“技能开发与验证”会话。本轮已实际读取并使用发布后的七项技能：

| 用户要求 | 活动技能 | 本项目采用结果 |
| --- | --- | --- |
| 产品设计 | `product-design` | 确定角色、任务页面、优先级与状态验收；将匿名示意与真实网络管理分开 |
| 前端 UI 设计 | `web-design` | 导航、信息层级、视觉令牌、表格与窄屏重排 |
| 前端框架设计 | `frontend-architecture` | 保留原生 ES 模块，明确状态权威和请求边界 |
| 前端代码开发 | `frontend-state` | 安全文本渲染、组合筛选、失败恢复、模态与焦点 |
| 后端框架设计 | `02-software-architect` | 保留现有 API / 网关运行边界；静态发布不触碰 VPN |
| 后端代码开发 | `backend-contract` | 对照实际响应与审计枚举，复核角色/Origin/CSRF 消费契约 |

数据库技能用于确认网络目录的增量迁移、稳定标识、并发版本校验及数据库与代码共同回滚；不为界面设计另建数据库、缓存或服务。

## 验收记录

2026-11-03，本轮静态与隔离验收结果：

- API 认证与跨站会话回归 33 项、静态打包 2 项通过。哈希资源名为可选发布参数，默认四文件产物保持兼容。
- 实际 Chrome 检查 375 × 812、768 × 1024、1440 × 1000 及默认桌面视口；整页无横向溢出，表格在自身区域滚动，窄屏刷新入口可用。
- 隔离 API 数据验证管理员/普通用户导航与授权展示、账户搜索和状态组合筛选、无结果提示、审计 20 + 4 条分页、列表失败后重试、错误密码后恢复及退出清理。
- 原生账户弹窗检查打开、取消、Escape 与关闭后焦点返回；编辑时停用账户名输入并将焦点移到密码。未提交生产账户或设备变更。
- 实际浏览器确认账户名 `pattern` 可编译并按预期校验；静态结构检查 ID、标签关联和本地 SVG 引用有效。没有新增第三方脚本或浏览器持久会话存储。

隔离数据仅证明界面状态和消费契约，不能替代线上权限或 VPN 连接验收。未单独完成原生 200% 缩放及完整辅助技术验收，不声明完整 WCAG 合规。线上发布结果、制品 SHA-256、恢复点及实际账户验收另记于本机交付记录。
